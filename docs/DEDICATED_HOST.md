# Выделенный хост: сервер мира без окна игры и без игрока (2026-11-01)

План: `docs/plans/2026-10-24-f3a-split-levels.md` §12. Раздельные карты: `docs/SPLIT_LEVELS.md` §7a. Безоконный режим: `engine/HEADLESS_AUDIT.md`.
Проверка в игре: `docs/checks/2026-11-01-dedicated-host.md`.

## Что это

Обычный хост это окно игры с игроком внутри. Выделенный хост это тот же exe с ключом `-coop_dedicated`: нет окна игры, нет игрока, есть настоящая консоль Windows.
Все игроки, включая владельца этого ПК, входят обычными клиентами.

Модель одной фразой: **хост, чей игрок навсегда стоит на служебной карте `fake_start` и ничего не делает.** Поэтому новых механизмов почти нет:

| Что | Как получается |
|---|---|
| Запуск без окна | тот же безоконный режим, что у сервера карты: WARP, без звука, без мьютекса (`g_coop_headless`) |
| Роли | `dedicated_roles()`: `WorldServer`, `MapAuthority`, без `Player` |
| Актёр | призрак, как у Mk: `mapserver::ghost_frame`, `ghost_actor()`. Ставится на `fake_start` в `on_alife_objects_loaded` |
| Карты | раздельные карты включены всегда (`game_split()`). Место хоста не играет (`Seat::plays = false`), поэтому карта с игроками всегда получает Mk |
| Сеть | те же порт и протокол. Для игроков хост просто стоит на другой карте |

## Запуск

```
AnomalyCoopDX11AVX.exe -fsltx fsgame_server.ltx -coop_dedicated [порт] -coop_new
AnomalyCoopDX11AVX.exe -fsltx fsgame_server.ltx -coop_dedicated [порт] -coop_load last
AnomalyCoopDX11AVX.exe -fsltx fsgame_server.ltx -coop_dedicated [порт] -coop_load "имя сейва"
```

- Порт по умолчанию 27960.
- `-coop_new` создаёт мир. `-coop_load last` берёт самый свежий сейв папки, `-coop_load <имя>` указанный.
- Без `-coop_new` и `-coop_load` окно ждёт команду `coop_world`.
- Свой `fsgame` обязателен: у сервера своя папка данных, иначе он делит сейвы и лог с игроком этого ПК. Лаунчер пишет `fsgame_server.ltx` сам. Mk получают `fsgame_ms<k>.ltx` из него.
- `-coop_hidden` (2026-11-12): окна консоли нет совсем. Ввод читается только из канала, который дал лаунчер. Конец канала значит, что лаунчер или игра хоста закрылись: сервер сохраняет мир и выходит. Строки в окно не пишутся, всё остаётся в логе.

### Сессия поднимается сама (2026-11-12)

Раньше автозапуск пробовал поднять сессию один раз. Если мир в этот кадр был не готов или порт занят, сервер оставался без сессии. Теперь он пробует каждый кадр, пока мир не готов, а после отказа повторяет через 5 с, потом реже, до 30 с.

| Строка лога | Что значит |
|---|---|
| `[coop] dedicated: waiting for the world (<причина>): level … g_actor … alive …` | мир ещё не готов; пишется один раз на каждую новую причину |
| `[coop] dedicated: the session is up on port P, N s after the level came` | сессия поднята |
| `! [coop] dedicated: gave up waiting for the world after N s: <причина>` | прошло 15 минут с появления уровня; дальше только `coop_host <порт>` руками |

Без `-coop_new` и `-coop_load` часы не идут: сервер ждёт `coop_world` сколько угодно.

## Консоль

Настоящее окно Windows (`AllocConsole`): правка строки и история стрелками работают сами. Лог старта виден с первой строки. Заголовок показывает порт, игроков и серверы карт.

| Строка | Что делает |
|---|---|
| `coop_players` | список: номер, ник, карта, пинг, потери, состояние |
| `coop_kick <номер\|ник> [причина]` | выкинуть игрока, персонаж остаётся в мире |
| `coop_autosave_now` | автосейв на ближайшем безопасном кадре |
| `coop_restore` | список автосейвов, свежий первым |
| `coop_restore <номер\|имя>` | мир откатывается, все игроки перезагружаются в него |
| `coop_time` | игровое время и множитель |
| `coop_time <чч[:мм]>` | мир идёт вперёд до этого часа, назад часы не ходят |
| `coop_status` | полная сводка сессии |
| `coop_world new\|last\|<сейв>\|list` | выбрать мир, пока его нет; `list` работает всегда |
| `coop_console_log 0\|1\|2` | что из лога показывать: ошибки, сессия, всё |
| `/go` | группа сразу идёт через выход, где её ждут |
| `say <текст>` | строка в чат всем игрокам |
| `quit`, `exit`, `stop`, Ctrl+C, закрытие окна | сохранить мир и выйти |

Команды `coop_players`, `coop_kick`, `coop_restore`, `coop_time` работают и у обычного хоста в консоли игры.

Если стандартный ввод процесса при старте это канал или файл, он читается рядом с окном. Этим лаунчер просит сервер завершиться: пишет `quit`.

## 16 мест

Место сервера мира не занято игроком, поэтому одновременно могут подключиться 16 клиентов. Клиенты соединяются с сервером
мира, который передаёт им потоки их карт. Оценка исходящей полосы по потокам клиентов равна
`out_игроков = Σ out_i ≈ число игроков × средний поток на игрока`.

| Ресурс | Как меняется нагрузка |
|---|---|
| Исходящий поток сервера мира | Замер 2026-10-20 на одной карте показал около 33 КБ/с снимков существ на клиента. С игроками и объектами оценка составляет 40–80 КБ/с на клиента, то есть 640–1 280 КБ/с (5,1–10,2 Мбит/с) на 16 клиентов, до накладных расходов сети. |
| Снимки игроков | На карте с `n` игроками каждый получает снимки остальных. Получается `n × (n − 1)` доставок за такт, то есть нагрузка растёт как `n²` на каждой карте. |
| Серверы карт и память | Предел равен `min(игроки + 1, srv_max_map_servers, 7)`, настройка по умолчанию равна 6. Замер 2026-11-13 дал около 1,0 ГБ на сервер мира и 1,0–1,4 ГБ на сервер карты. Для семи серверов карт оценка составляет 8,0–10,8 ГБ суммарно по этим процессам. |
| Номера объектов | Номера 16-битные. Серверы карт получают до семи диапазонов по 4 095 номеров от `0x9000`. Аренда на 16 клиентов занимает до `16 × 48 = 768` номеров. В оценке плана при семи диапазонах оставалось около 9 500 номеров. 16 персонажей с вещами по 150 объектов дают ещё около 2 400 объектов. |

В консоли сервера мира выполните `srv_netstats`. Строка `@rl net peer=<id> out=<Б/с> in=<Б/с>` показывает направления
со стороны сервера мира за пять полных секунд с обновлением каждые 250 мс. Сумма `peer=total` включает активные
клиентские соединения и мосты серверов карт. Для оценки внешней полосы складывайте только строки клиентов. `out` считает
пакеты, принятые ENet к отправке, `in` считает полученные пакеты. Оба направления учитывают данные сообщений и их
двухбайтовый тип. Полную полосу с заголовками, подтверждениями и повторными передачами замеряют на сетевом интерфейсе.

Нативный стенд `seat_bench_server_sixteen_clients_ten_seconds` передавал по loopback каждому из 16 клиентов пакеты
1 100 Б при 15 Гц по ненадёжной полосе и 200 Б при 5 Гц по надёжной в течение 10 секунд.
Расчётная нагрузка равна `16 × (1 100 × 15 + 200 × 5) = 280 000 Б/с`. В прогоне доставлены 2 400 из 2 400
ненадёжных и 800 из 800 надёжных пакетов. Измерено 279 978 Б/с исходящих и 0 Б/с входящих данных. Средний вызов
`Session::update` на хосте занял 96,5 мкс за кадр при 600 кадрах. Этот прогон измеряет транспорт на одном ПК.

## Лаунчер

Кнопка «Сервер на этом ПК» в боковой панели. Карточка: выбор мира, порт, запуск. Когда сервер работает: порт, «Войти в игру», «Сохранить и остановить», список команд.

- Exe запускается под именем `bin\RayLinkServer.exe` (жёсткая ссылка). Mk наследуют это имя, поэтому «игра запущена» и «сервер запущен» лаунчер различает по имени процесса.
- Папка сервера: `%APPDATA%\RayLink\server\<игра>`, отдельно от профилей игроков.
- Сервер переживает закрытие лаунчера. Тогда лаунчер видит его по процессу, а остановить можно только из окна сервера.
- «Играть» при работающем сервере этого стенда запускает игру с `-coop_connect 127.0.0.1:<порт>`.

## Проверка без игрока (2026-11-12)

Стенд — корень игры, который сделал лаунчер (один общий `gamedata`), например `E:/RayLinkGames/GAMMA/game-dev`.

| Шаг | Команда |
|---|---|
| Наложить слои Core и GAMMA и exe из `engine-ci` на стенд, сохранив заменённое | `python -I tools/stand_overlay.py <стенд> <папка бэкапа>` (`--dry` только показать) |
| Завести серверу свою папку данных (`fsgame_server.ltx`, `appdata_server`) | `powershell -ExecutionPolicy Bypass -File tools/stand_server.ps1 -Stand <стенд>` |
| Скрытый сервер: новый мир или последний сейв, команды по каналу, закрытие канала | `powershell -ExecutionPolicy Bypass -File tools/ded_check.ps1 -GameDir <стенд> -World new\|last -Port 27991 -Bom` |
| Спросить работающий сервер через консоль (Lua через `run_string`, нужен `-dbg`) | `tools/ded_probe.ps1 -Lua ... -Commands ...` |

`ded_check.ps1` ждёт строку `the session is up`, шлёт `coop_status` и `coop_players`, закрывает канал и ждёт `the world is saved, the host goes down`. Последняя строка вывода — `PASS`.

Жёсткие ссылки (ТЗ Р21, 2026-11-19): файлы стенда лаунчера — жёсткие ссылки на файлы модов MO2. `stand_overlay.py` и
`stand_server.ps1` в существующий файл стенда не пишут: старое имя удаляется, новый файл получает имя, файл мода остаётся
прежним (`tools/mo2_stand.py` `replace_file`, помощники `tools/stand_common.ps1`). Через папку-junction оба отказывают.

Оверлей кладёт на стенд **рабочее** дерево, неотслеживаемые файлы тоже: стенд после него гоняет код, которого нет ни в одном
коммите. Это ручная проверка, а не метка. Что оверлей добавил и какие файлы модов перекрыл, он записывает в сам стенд
(`.raylink-head-deploy.json`); `tools/stand_srv.ps1` и `tools/stand_hostplay.ps1` первым шагом выкладывают HEAD
(`tools/stand/stand_head.py deploy`), уносят всё, чего нет в HEAD и в манифесте лаунчера, и возвращают файлы модов.
Проверка сервера для выпуска — только `tools/stand_srv.ps1` (метка `srv.ok`), не эти шаги (`docs/MODES.md`, раздел 10).

Консоль обрезает длинную строку и переводит её в нижний регистр: Lua слать короткими строками, имена только строчные.

**Что нашла первая проверка на сборке 44.** Сессия не поднималась: актёр сервера — призрак, который ни за чем не наблюдает, и правило «объект выходит в онлайн рядом с ближайшим наблюдателем» применялось к нему самому. Без объекта актёра нет `g_actor`, `world_up()` ложно. Исправлено в `coop::switch_vote` (движок `5498e3fb`): актёр выделенного хоста всегда в онлайне. После исправления новый мир GAMMA поднимает сессию примерно через 15 с после появления уровня, загрузка сейва — через 13 с.
